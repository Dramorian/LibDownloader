## C. Серьёзные дефекты кода

### C1. Голый `slug` нельзя отправить из формы — браузер блокирует submit
`app.html:71` — `<input id="source-url" type="url">`, у `<form id="source-form">` нет `novalidate`.
Значение `87161--san-da` или `mangalib.me/ru/7965--...` невалидно для `type=url`, поэтому нативный constraint validation отменяет `submit`, и `loadTitle()` не вызывается. Пользователь видит браузерный пузырёк «введите URL», хотя весь продукт и подсказка рядом обещают работу с голым slug (и `parseSlug` в `core.js:118` его поддерживает).

**Проверка:** вставить в поле `87161--san-da` → нажать «Загрузить список» → ничего не происходит.

**Фикс:** `type="text"` (валидация всё равно своя, в `loadTitle`) либо `novalidate` на форме.

### C2. Bearer-токен уходит на все запасные API-хосты, а не «только на lib.social»
`app.js:48-54` (`makeApiHeaders` подставляет `Authorization`) + `app.js:531` (`apiGet` строит заголовки один раз) + цикл `for (const base of bases)` → при первом же сбое основного API тот же токен отправляется на `hapi.hentaicdn.org`, `api2.mangalib.me`, `api.cdnlibs.org`, `api.shlib.life`.
`README.md` (раздел «Как устроено») прямо утверждает: «отправляет его как `Authorization: Bearer …` **только на API `lib.social`**». Код и обещание расходятся.

**Фикс:** добавлять `Authorization` только для хостов из белого списка (`api.lib.social`, `api.cdnlibs.org` — как решит продукт) внутри `apiGet`, а не в общем `makeApiHeaders`; в `fetchJsonInPage` не передавать токен в MAIN-мир без нужды.

### C3. При 404-фолбэке на другой `Site-Id` состояние сайта остаётся рассинхронизированным
`app.js:616-630`: при находке тайтла на другом сайте меняются только `state.siteId` и `state.siteName`. При этом:
- `state.site`, `state.siteKey`, `state.origin` — от старого сайта, а `state.origin` уходит в DNR-правило как `Referer` (правило потом переустанавливается с чужим Referer);
- `state.apiBases`, `state.fallbackServers` — от старого сайта, то есть страницы главы будут искаться на CDN другого профиля;
- `state.bridgeTabId`/`findSourceTab` продолжают требовать вкладку **старого** сайта (`site.key`), хотя запросы теперь идут с другим `Site-Id`.

Итог: для «того же slug на другом сайте сети» (HentaiLib/RanobeLib) главы, скорее всего, не скачаются, хотя список загрузится.

**Фикс:** при переключении `siteId` пересобирать производные поля (`site`, `siteKey`, `origin`, `apiBases`, `servers`) из `C.SITE_NAMES`/профиля и сбрасывать `apiBase`, `serversLoaded`, `bridgeTabId`.

### C4. Поиск похожих тайтлов и 404-фолбэк ходят только в первый API-базис
`app.js:620` и `app.js:645`: `bases: [state.apiBases[0]]`.
Если первый базис недоступен (типичная ситуация: `api.shlib.life` лежит, работает `api.cdnlibs.org`) — вся ветка восстановления после 404 падает, и вместо «похожих тайтлов» пользователь получает ошибку.

Плюс в `fetchChaptersWithFallback` при `!altErr.notFound` исключение пробрасывается наружу (`app.js:630`), то есть сетевая ошибка на первом же альтернативном `Site-Id` обрывает перебор остальных и **скрывает исходную ошибку 404**.

**Фикс:** не сужать `bases`; ловить все ошибки внутри цикла и продолжать перебор.

### C5. Таймаут сохранения файла «успешно» завершает загрузку через 60 с
`app.js:875`: `timer = setTimeout(() => finish(null, downloadId), 60000)` — при потере события `onChanged` промис резолвится как успех **и** `URL.revokeObjectURL(objectUrl)` (`app.js:845-857`) освобождает Blob.
Для больших архивов (сотни мегабайт, режимы «Один …») запись на диск может длиться дольше минуты: тогда ссылка на blob отзывается во время скачивания, файл обрывается, а интерфейс рапортует «Готово».

**Фикс:** на таймауте — `reject` с понятным текстом (или проверять `chrome.downloads.search({id})`), и не отзывать URL, пока состояние не `complete`/`interrupted`.

### C6. Права на новые CDN запрашиваются *до* того, как CDN узнан
`app.js:1612` (`requestHostAccess()` в обработчике клика) → `app.js:1481-1482`: `state.accessPromise` ожидается раньше `loadImageServers()`. Список серверов из `/constants` появляется уже после `chrome.permissions.request({origins: allOrigins()})`, поэтому новые хосты в запрос не попадают; дальше их запросы падают по CORS и уходят в запасной путь через вкладку сайта (а если вкладки нет — в ошибку «Нет открытой вкладки нужного сайта»).

**Фикс:** сначала `loadImageServers()`, затем `chrome.permissions.request` (клик пользователя ещё «живой» не будет — поэтому лучше запрашивать сразу `https://*/*` из `optional_host_permissions` либо запрашивать при появлении неизвестного хоста отдельным действием).

### C7. Память: архив собирается минимум в двух-трёх копиях
`core.js:395-402` (`concatBytes` копирует всё в один `Uint8Array`) → `C.buildZip` заворачивает его в `Blob` (ещё копия/сериализация), а в режиме «папки по главам» перед этим ещё `buildZipBytes` на каждую главу. При этом исходные байты страниц всё это время лежат в `archiveChapters`.
Пик памяти ≈ 2× размер архива + сами страницы. 100 глав × 30 страниц × 400 КБ ≈ 1.2 ГБ → вкладка падает по OOM раньше, чем появится ошибка. `README.md` предупреждает об этом в общем виде, но реализация не деградирует мягко.

**Фикс:** собирать архив как массив частей (`Blob([part, part, …])`) без `concatBytes`, отпускать `bytes` после упаковки главы, добавить порог с предупреждением.

### C8. ZIP32 без проверок: >4 ГБ и >65 535 файлов дают битый архив
`core.js:407-465`: `setUint32` на смещения/размеры (`:454`, `:463`) и `end.setUint16(8, files.length)` (`:460`) молча переполняются. Плоский режим «Один CBZ — сплошные страницы» считает записью каждую страницу, так что 65 535 страниц — достижимо для большой пакетной загрузки; 4 ГБ — тоже.

**Фикс:** проверять `files.length < 0xFFFF` и `offset + size < 0xFFFFFFFF`, иначе выдавать понятную ошибку («слишком большой архив, качайте частями»).

## M. Средние дефекты

### M1. Главы без тома получают метку `т_manga`
`core.js:200-206` + `core.js:263`:
```js
padNumber('', 2)          // → "_manga"
chapterLabel({volume:'', number:'1'})  // → "т_manga гл0001"
```
`sanitizeComponent('')` возвращает `_manga`, поэтому такая метка попадает в интерфейс, в `chapters.txt`, в имена папок и в `ComicInfo.xml`. Ваншоты и тайтлы без томов читаются как мусор.

**Фикс:** отдельная ветка `padNumber` для `''`/`undefined` → `''`, и `chapterLabel` без префикса `т…`, если тома нет.

### M2. Пустой параметр `volume=` уходит в API
`app.js:935`: `new URLSearchParams({ number, volume })` — при пустом томе получается `volume=`. Для главы без тома запрос может вернуть 404/пустой список, хотя страницы существуют.

**Фикс:** добавлять `volume` только если значение непустое.

### M3. Кнопка «Выделить» с пустым полем выделяет **всё**
`core.js:parseRange('')` возвращает все главы (это зафиксировано тестом) → `app.js:1296-1305`. Пользователь нажимает «Выделить», забыв заполнить диапазон, и получает выделение всех глав — опасное поведение рядом с кнопкой «Скачать выбранные».

**Фикс:** в UI пустой диапазон считать ошибкой («укажите диапазон»), а «все» оставить кнопке «Выбрать все».

### M4. Папка в загрузках сбрасывается при каждой загрузке тайтла
`app.js:1370`: `dom.root.value = state.rootFolder`. Пользовательский путь, введённый вручную, затирается при следующем «Загрузить список» (и при переключении тайтла из подсказок).

**Фикс:** подставлять папку только если поле не менялось пользователем (или сохранять в `chrome.storage`).

### M5. Пустой список глав показывает «рабочую область» без глав
`app.js:1394-1395`: `dom.workspace.hidden = false` выставляется **до** проверки `if (!state.chapters.length)`. В итоге при лицензированном/пустом тайтле видны пустая таблица с рамками, `Выбрано: 0`, настройки и активная кнопка «Скачать выбранные», которая ругается в статус.

**Фикс:** для пустого списка — отдельное состояние (скрыть `#workspace`, показать объяснение), а `#start-btn` держать `disabled`.

### M6. В 404-фолбэке пропадает исходная ошибка
См. C4: `throw altErr` вместо `throw err` — пользователь видит сетевую ошибку чужого сайта вместо «тайтл не найден».

### M7. Нет сохранения настроек
В `manifest.json` нет `"storage"`, в коде нет `chrome.storage`. Формат, скорость, имя папки, последний тайтл сбрасываются при каждом открытии вкладки. Для инструмента, которым пользуются повторно, это заметная потеря.

### M8. Дублирование доменных списков между `background.js` и `core.js`
`background.js:9-31` повторяет `SITE_INITIATOR_DOMAINS`/`SITE_DNR_DOMAINS` из `core.js:60-72` руками. Списки уже разошлись: `SITE_DNR_DOMAINS` (`core.js:66`) не содержит `api2.mangalib.me`, хотя этот хост есть и в `background.js:15`, и в `manga.apiBases` (`core.js:24`). При добавлении очередного зеркала расхождение будет только расти.

**Фикс:** `"background": { "service_worker": "background.js", "type": "module" }` + `import` констант из `core.js`.

### M9. Молчаливые `catch (_) {}` вокруг критичных мест
`app.js:442` (`readPageContext`) глотает **все** ошибки: отсутствие host-permission, закрытая вкладка, запрет `scripting` — всё выглядит как «токена нет». То же в `app.js:1411` (`loadImageServers().catch(() => {})`). Диагностика в README обещает понятные сообщения, но здесь их не будет.

**Фикс:** логировать причину в `#log` (хотя бы в `err`-строке, не в статусе).

### M10. `fetchBinaryDirect`: `cache: 'force-cache'` без валидации
`app.js:742-743`. Для CDN с переиспользуемыми URL и для повторных прогонов это может вернуть устаревший/чужой файл из кеша; ошибка проявится уже в архиве. Достаточно `default`/`no-cache`.

### M11. `Retry-After` понимает только число
`app.js:282-286`: HTTP-дата (`Retry-After: Wed, 21 Oct 2026 07:28:00 GMT`) даёт `NaN` → 0 → повтор сразу, что при 429 только ухудшает ситуацию.

### M12. Мелочи в `core.js`
- `parseSlug('javascript:alert(1)')` → `'alert(1)'`, `parseSlug('ftp://mangalib.me/ru/1--x')` → `'1--x'`: проверяется только `startsWith('http')` при *неподдерживаемом* хосте, схема не валидируется.
- `chapterLabel` для `volume:'0'` даёт `т00` (том 0 обычно означает «нет тома»).
- `buildComicInfo({pageCount:1})` без `chapterNumber` даёт `<Title>Глава undefined</Title>` (`core.js:346`).
- `folderedArchiveEntries` ставит в `<Number>` общий диапазон строкой (`т01 гл0001–т01 гл0005 (5 глав)`) — многие ридеры ждут там число; заодно `<Volume>` берётся только у первой главы.
- `nestedArchiveEntries` (`single-zip`) не проверяет уникальность имён `.cbz` после обрезки до 90 символов.

## D. Дизайн, UX и доступность

### D1. Закрытые главы падают до контраста ~2:1
`app.css:247`: `.chapter-row.unavailable { opacity: .5 }`.
`--muted #526978` при 50 % поверх `#F6F7F4` даёт ≈ `#A4B0B6` → **2.06:1** (норма AA — 4.5:1). Одновременно `opacity` гасит и бейдж «закрыто» (`--stamp` в 10 px), то есть единственный маркер недоступности тоже становится нечитаемым. В `DESIGN.md` при этом заявлены «closed rows are muted, not hidden» и контраст `muted 5.35:1`.
**Фикс:** не снижать прозрачность всей строки — приглушать только номер/название до реального AA-цвета (`#5B707C` и темнее) и оставлять бейдж в полную силу.

### D2. Мобильная сетка строки главы разваливается на 3 полосы
`app.css:237` (5 колонок, 5 детей) и `app.css:306-307`:
```css
.chapter-row { grid-template-columns: 26px 96px minmax(80px,1fr) 64px; }
.chapter-row select { grid-column: 2 / 5; }
```
На ширине ≤760 px: чекбокс/номер/название занимают 1-ю строку, `select` (или текстовый див перевода) уезжает на 2-ю (колонки 2–4), а `.chapter-badge` — на 3-ю в первую колонку. Бейдж «закрыто» / «2 пер.» болтается слева отдельной строкой, и каждая строка получает лишнюю пустую полосу высотой с бейдж.
**Фикс:** спрятать бейдж в мобильном брейкпоинте (он дублирует состояние чекбокса и `select`) либо явно задать `grid-template-areas`.

### D3. Строка главы подсвечивается при наведении, но не кликабельна
`app.css:246`: `.chapter-row:hover { background: var(--blue-wash); }` — визуально обещает клик по всей строке, а переключается только 16×16 чекбокс (`app.css:249`). Для отбора десятков глав это главная операция — попадание в 16 px мышью раздражает.
**Фикс:** `<label>` на всю строку или обработчик клика по `row` (исключая `select` и текст с `title`). Одновременно это поднимет touch-таргет.

### D4. `DESIGN.md` обещает touch-таргеты ≥40 px — в строках их 32 px
`.chapter-row` = 8 px padding + 16 px чекбокс = 32 px; `.branch-select` (`app.css:260`) ≈ 26 px по высоте. На мобильном это ниже и 44 px (Apple), и 40 px из собственного документа.

### D5. Нет подписей у фильтра и диапазона
`app.html:135-136`: только `placeholder`, `<label>` нет. Скринридер получает «search, Фільтр…»/поле без имени, а после ввода подсказка исчезает и пользователь не помнит, что это за поле. Заодно `#chapter-list` (`role="list"`) не связан с `#chapters-heading` через `aria-labelledby`.

### D6. `<progress>` без доступного имени
`app.html:150-158`: два `<progress>` без `aria-label`/`aria-labelledby`; текст рядом (`#overall-text`, `#current-text`) с ними программно не связан. Прогресс читается как «progress bar 0 %» без контекста.

### D7. Подсказки оформлены сеткой, хотя в `DESIGN.md` — «plain list, no card grid»
`app.css:211`: `repeat(auto-fill, minmax(260px, 1fr))`. В рабочей колонке ~780 px это 2–3 колонки «равных карточек», что прямо противоречит и `DESIGN.md` («Suggestions: plain list of text buttons, no card grid»), и `PRODUCT.md` («equal card grid» — «what would feel wrong»).

### D8. Три раза один и тот же текст про частичный архив
`app.html:54-56` (rail-note), `app.html:132` (`archive-note`), плюс статус при старте (`app.setStatus` в `startDownload`) и ещё раз в `details`. На первом экране из-за этого две трети текста — повторение одной мысли, а собственно данные (тайтл, главы) уезжают вниз.
**Фикс:** оставить одно место рядом с кнопкой «Скачать выбранные».

### D9. Правая колонка-«докет» — статичная декорация после первой загрузки
`#site-badge` и `#api-host` — две строки данных, ради которых держится 220 px + 26 px отбивки на всю сессию; «Порядок работы» и «rail-note» — постоянный текст. Для Operate-поверхности это противоречит `PRODUCT.md` («no decorative containers», «one clear column of work»). Разумно: после успешной загрузки прятать «Порядок работы» или переносить «Сведения» в строку заголовка.

### D10. У кнопки «Остановить» нет hover-отклика
`app.css:159-160`: базовый `.button:hover:not(:disabled)` даёт заливку, а `.button.danger:hover:not(:disabled)` возвращает `background: transparent; border-color: var(--stamp)` — то есть состояние наведения совпадает с обычным. Для аварийной кнопки это плохо: не видно, что она живая.

### D11. Тач-цели и «опасные» действия рядом
`Скачать выбранные` (primary) и `Остановить` (danger) стоят на одной строке через 8 px, а «Обновить доступ» уезжает вправо через `margin-left: auto`. При промахе на тач-экране легко нажать Stop вместо Start (первая же глава будет считаться остановленной).

### D12. Мелкая типографика вне заявленной шкалы
`DESIGN.md` фиксирует шкалу 13/15/17/21/34. В CSS реально есть 10 px (`.chapter-badge`), 11 px (`.pill`, `.docket dt`, `.log li`), 12 px (`.chapter-num`, `.selection-count`), 14 px (`.rail-title`, `.size-sm`), а `h1` — `clamp(26px, 3.6vw, 38px)` (`app.css:67`), то есть до 38 px. Данные читаются 10–11 px моно — на 1120 px-листе это заметно мелко (и `10px` бейджа ещё и уходит в `opacity .5`, см. D1).
Плюс `#source-url` держит в `placeholder` два полных URL — они гарантированно обрезаются, то есть подсказка не работает.

### D13. Фокус после загрузки не переносится
После «Загрузить список» список глав появляется ниже статуса, но фокус остаётся на кнопке; клавиатурному пользователю нужно протабать все настройки. Диапазон при этом выделяется только `Shift + клик` — с клавиатуры недоступен (`Shift + стрелки` на чекбоксах обрабатываются только для одного).
**Фикс:** `#chapters-heading` с `tabindex="-1"` и `focus()` после успешного рендера; обрабатывать `keydown` с `shiftKey` для диапазона.

### D14. Мелочи оформления
- Иконка в `app.html:14-21` содержит жёсткий `fill="#A63D32"` — цвет токена (`--stamp`) продублирован в разметке; при смене палитры знак отстанет.
- `input, select { outline: none }` (`app.css:129`) ничего не добавляет (перебивается `:focus-visible` по специфичности), но мешает будущим правкам фокуса.
- Отключённые подсказки: `.suggestion:disabled { opacity: .5 }` (`app.css:226`) — та же проблема контраста, что D1.
- В `fonts/` лежат неиспользуемые подмножества: вьетнамский (5 файлов), греческий (3), cyrillic-ext (5) — из 38 `@font-face` нужны примерно 18; ~300–350 КБ payload впустую.
- Горизонтальные скроллеры `.chapter-list` (420 px) и `.log` (170 px) — два вложенных скролла внутри страницы; при 100+ главах действие «Скачать» уезжает за пределы списка, а панель действий не `sticky`.

## T. Тесты, документация, процесс

### T1. `README.md` обещает jsdom-прогон, которого нет
`README.md:187`: «Дополнительно jsdom-прогон проверяет обычный и частичный архив после "Остановить"…». В репозитории нет `package.json`, jsdom не подключён, `tests/` — три файла на `node:test` и `core.js`. Сценарий «нажали Остановить → получили частичный архив» не проверяется вообще.

### T2. Логика в `app.js` не тестируема by design
1674 строки с глобальным `state`, DOM-узлами и `chrome.*` в одном файле: `collectChapterFiles`, `saveBatchArchive`, `folderedArchiveEntries`, `startDownload` нельзя вызвать из теста без подделки всего `chrome`. Проще всего вынести чистые функции (`flatArchiveEntries`, `folderedArchiveEntries`, `nestedArchiveEntries`, `reindexFiles`, `sortedPages`, `batchRangeLabel`) в `core.js` и покрыть их — сейчас они проверяются только глазами.

### T3. Часть тестов ничего не проверяет или ломается при рутинных правках
- `tests/design.test.mjs:76` «design docs describe the committed world» лишь проверяет, что в доках есть слова «circulation slip»/«Operate».
- `tests/static.test.mjs:15` жёстко фиксирует `version === '1.6.0'` — любой релиз требует правки теста.
- `tests/design.test.mjs:40` запрещает подстроку `border-left:` целиком (включая законные применения) и `→` в JS — это запрет на символ, а не на паттерн.
- Инвертированные проверки вроде `assert.doesNotMatch(html, /\bhero\b/i)` ловят слово, а не проблему.

### T4. `DESIGN.md` ссылается на отсутствующие артефакты
`DESIGN.md:94`: «`npx impeccable detect --json app.html app.css` returns `[]`» — версия инструмента не зафиксирована, в репозитории нет ни `package.json`, ни lock-файла, воспроизвести проверку нельзя.
`DESIGN.md:96`: «`preview.html` is a static self-contained render…» — файла `preview.html` в репозитории нет.

### T5. `README.md` описывает сборку, которой нет
`README.md:30`: «Распакуйте `mangalib-downloader.zip`» — в репозитории нет ни архива, ни скрипта сборки. Раздел «Структура» рисует дерево с корнем `mangalib-downloader/`, а репозиторий плоский и лежит в корне. Пользователь, пришедший по README, не найдёт ни файла, ни папки.

### T6. `manifest.json` и продукт
- `optional_host_permissions: ["https://*/*"]` — фактически «доступ ко всему интернету одним подтверждением»; после C6 он ещё и запрашивается не в тот момент (до Discover CDN), то есть пользы не приносит, а насторожить ревью Chrome Web Store может.
- Нет `"storage"` → нет сохранения настроек (M7).
- `minimum_chrome_version: 116` при использовании `world: 'MAIN'` в `scripting.executeScript` (появился в 95/111) — ок, но нигде не объяснено; стоит либо снизить, либо записать причину.
